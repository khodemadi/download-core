# هسته دانلود منیجر Rust

یک هسته سریع، دقیق و قابل توسعه برای دانلود فایل‌ها با استفاده از زبان **Rust**.

این پروژه برای ساخت یک Download Manager طراحی شده و از دانلود چنداتصالی، ادامه دانلود، تقسیم فایل به بخش‌های مختلف و بررسی صحت فایل پشتیبانی می‌کند.

## ✨ قابلیت‌ها

- 🚀 دانلود سریع با استفاده از چند اتصال هم‌زمان
- ⭐ سیستم سطح‌بندی اتصال‌ها از ۱ تا ۵ ستاره
- 📦 تقسیم فایل به چند Segment
- 🔄 امکان ادامه دانلود پس از قطع شدن اتصال
- 🔁 تلاش مجدد خودکار در صورت خطا
- ⏱️ استفاده از Exponential Backoff برای Retry
- 💾 مصرف بهینه حافظه با استفاده از Streaming I/O
- 🌐 استفاده از HTTP Range Request
- 🛡️ بازگشت خودکار به دانلود تک‌اتصالی در صورت پشتیبانی نکردن سرور از Range Request
- 🔐 امکان بررسی صحت فایل با SHA-256
- 🧩 ترکیب Segmentها با ترتیب صحیح
- 💥 ذخیره وضعیت دانلود برای کمک به بازیابی پس از Crash
- 🦀 نوشته شده کاملاً با Rust
- 🧱 معماری Core جدا از CLI برای توسعه آسان‌تر

---

## ⭐ سیستم ستاره‌ها

تعداد ستاره‌ها میزان اتصال‌های موازی برای دانلود را مشخص می‌کند.

| سطح | تعداد پارت ها |
|---|---:|
| 🟢 Basic | 1 |
| 🔵 Standard | 2 |
| 🟣 Advanced | 4 |
| 🟠 High | 8 |
| 🔴 Maximum | 16 |

###چرا از چند اتصال استفاده کنیم؟

یک فایل بزرگ را می‌توان به چند بخش مستقل تقسیم کرد.

برای مثال، با ۴ اتصال هم‌زمان:
```
اتصال ۱ ← بخش ۱
اتصال ۲ ← بخش ۲
اتصال ۳ ← بخش ۳
اتصال ۴ ← بخش ۴
```
پس از اینکه تمام بخش‌ها دانلود شدند، آن‌ها به ترتیب صحیح با یکدیگر ترکیب می‌شوند تا فایل نهایی ساخته شود.

توجه داشته باشید که اتصال‌های بیشتر همیشه به معنی سرعت بالاتر نیستند. برخی سرورها ممکن است تعداد اتصال‌های هم‌زمان را محدود کنند یا با تعداد اتصال‌های کمتر عملکرد بهتری داشته باشند.

### توضیح فایل‌ها

**`downloader.rs`**

هسته اصلی دانلود را مدیریت می‌کند؛ شامل دانلود تک‌اتصالی، دانلود چنداتصالی، مدیریت Segmentها و ترکیب فایل‌ها.

**`segment.rs`**

فایل را به بخش‌های مختلف تقسیم می‌کند.

**`retry.rs`**

منطق Retry و Exponential Backoff را مدیریت می‌کند.

**`verify.rs`**

برای محاسبه Hash فایل با الگوریتم SHA-256 استفاده می‌شود.

**`types.rs`**

Typeهای اصلی پروژه مانند وضعیت دانلود، Progress و Star Level در این فایل قرار دارند.

**`error.rs`**

خطاهای مختلف دانلود و سیستم را مدیریت می‌کند.

**`lib.rs`**

API اصلی Core را در اختیار پروژه‌های دیگر قرار می‌دهد.

**`main.rs`**

یک CLI ساده برای اجرای Download Core است.

## 📚 استفاده به‌عنوان Library

می‌توانید Core را مستقیماً در یک پروژه Rust دیگر نیز استفاده کنید.

مثال:

```rust
use rust_download_core::{
    DownloadManager,
    DownloadOptions,
    StarLevel,
};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let manager = DownloadManager::new()?;

    let report = manager
        .download(
            "https://example.com/file.zip",
            "./file.zip",
            DownloadOptions {
                stars: StarLevel::Five,
                ..Default::default()
            },
        )
        .await?;

    println!("File: {}", report.path.display());
    println!("Bytes: {}", report.bytes);

    Ok(())
}
```

## 🔐 بررسی SHA-256

در صورت نیاز می‌توان SHA-256 فایل دانلودشده را بررسی کرد.

این قابلیت کمک می‌کند مطمئن شوید فایل دانلودشده با Hash مورد انتظار مطابقت دارد.

در صورت عدم تطابق Hash، دانلود با خطای Verification شکست می‌خورد.

---

## 🔄 Resume

اگر دانلود چنداتصالی در هنگام دانلود قطع شود، وضعیت Segmentها در یک Manifest ذخیره می‌شود.

ساختار موقت دانلود به شکل زیر خواهد بود:

```text
file.download/
├── manifest.json
├── segment-0.part
├── segment-1.part
├── segment-2.part
└── ...
```

در اجرای مجدد، Segmentهایی که قبلاً کامل شده‌اند دوباره دانلود نمی‌شوند.

---

## 🔁 Retry

در صورت بروز خطای موقت شبکه، سیستم چند بار تلاش می‌کند دانلود Segment را ادامه دهد.

برای جلوگیری از فشار بیش از حد به سرور، بین تلاش‌ها از **Exponential Backoff** استفاده می‌شود.

---

## 🌐 پشتیبانی از HTTP Range

در حالت چنداتصالی، فایل با استفاده از HTTP Range Request به بخش‌های مختلف تقسیم می‌شود.

برای مثال:

```text
Connection 1 → Bytes 0 - 999999
Connection 2 → Bytes 1000000 - 1999999
Connection 3 → Bytes 2000000 - 2999999
Connection 4 → Bytes 3000000 - 3999999
```

پس از پایان دانلود، تمام Segmentها به ترتیب صحیح با یکدیگر ترکیب می‌شوند.

---

## ⚠️ نکته مهم

برای استفاده از دانلود چنداتصالی، سرور باید از HTTP Range Request پشتیبانی کند.

اگر سرور از Range پشتیبانی نکند یا اندازه فایل مشخص نباشد، Core به‌صورت خودکار از دانلود تک‌اتصالی استفاده می‌کند.
